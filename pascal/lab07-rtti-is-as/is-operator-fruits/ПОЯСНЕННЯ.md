# Пояснення до проєкту «Lab7_1_Fruits»
## Тема: Використання оператора `is` у Delphi (ООП)

---

## 1. Ієрархія класів

```
TFruit           ← базовий клас (фрукт)
├── TApple       ← нащадок (яблуко)
└── TPear        ← нащадок (груша)
```

`TApple` і `TPear` оголошені як порожні класи-нащадки `TFruit`.
Вони успадковують поле `name` та конструктор `Create` від батьківського класу.

---

## 2. Клас TFruit

```pascal
TFruit = class
Public
  name: String;
Published
  Constructor Create(name: String);
end;
```

- `name` — відкрите поле, зберігає назву фрукта.
- Конструктор `Create` приймає рядок і зберігає його у `Self.name`.
  `Self` тут — вказівник на конкретний екземпляр об'єкта, що створюється.

---

## 3. Реалізація конструктора

```pascal
Constructor TFruit.Create(name: String);
begin
  Self.name := name;
end;
```

Параметр `name` має те саме ім'я, що й поле класу.
Щоб відрізнити поле від параметра, використовується `Self.name`.

---

## 4. Обробник FormCreate — покрокове пояснення

### Крок 1 — оголошення змінних
```pascal
var
  fruit : TFruit;
  apple : TApple;
  pear  : TPear;
```
Три локальні об'єктні змінні. На початку вони містять `nil` (не вказують ні на що).

### Крок 2 — створення об'єктів
```pascal
apple := TApple.Create('Антонівка');
pear  := TPear.Create('Бера');
```
Викликаємо конструктор, унаслідований від `TFruit`.
Після цього `apple.name = 'Антонівка'`, `pear.name = 'Бера'`.

### Крок 3 — перевірка: чи є яблуко фруктом?
```pascal
if apple is TFruit then
  ShowMessage(apple.name + ' - фрукта');
```
`is` перевіряє, чи об'єкт належить до вказаного класу **або його нащадка**.
`TApple` є нащадком `TFruit`, тому умова **істинна** → виводиться «Антонівка - фрукта».

### Крок 4 — перевірка: чи є груша фруктом?
```pascal
if pear is TFruit then
  ShowMessage(pear.name + ' - фрукта');
```
Аналогічно → виводиться «Бера - фрукта».

### Крок 5 — поліморфне присвоєння
```pascal
fruit := apple;
```
Змінній базового класу `TFruit` присвоюємо адресу об'єкта `TApple`.
Це можливо, бо `TApple` є нащадком `TFruit`.
Обидві змінні тепер вказують на **той самий об'єкт** у пам'яті.

### Крок 6 — чи є fruit яблуком?
```pascal
if fruit is TApple then
  ShowMessage(apple.name + ' - яблуко');
```
Попри те що змінна оголошена як `TFruit`, оператор `is` визначає
**реальний тип** об'єкта під час виконання (RTTI).
Реальний тип — `TApple` → умова **істинна** → «Антонівка - яблуко».

### Крок 7 — чи є fruit грушею?
```pascal
if fruit is TPear
  then ShowMessage(apple.name + ' - груша')
  else ShowMessage(apple.name + ' - це не груша!');
```
Реальний тип — `TApple`, не `TPear` → умова **хибна** → «Антонівка - це не груша!».

> **Примітка:** Вираз `if apple is TPear` не компілюється, бо компілятор
> статично знає, що `TApple` і `TPear` не пов'язані між собою.
> Через змінну базового типу `fruit` така перевірка допустима.

| № | Повідомлення               |
|---|----------------------------|
| 1 | Антонівка - фрукта         |
| 2 | Бера - фрукта              |
| 3 | Антонівка - яблуко         |
| 4 | Антонівка - це не груша!   |

---

## 6. Висновок

Оператор `is` у Delphi:
- перевіряє належність об'єкта до класу **під час виконання** (не під час компіляції);
- повертає `True`, якщо об'єкт є екземпляром вказаного класу або будь-якого його нащадка;
- дозволяє безпечно працювати з поліморфними посиланнями базового класу.
